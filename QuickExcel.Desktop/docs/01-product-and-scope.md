# QuickExcel 产品范围

QuickExcel 面向需要在本地处理表格、愿意用少量 JavaScript 表达业务规则的用户。核心体验是：打开现有数据，编辑与计算，将规则和数据一起保存为 `.xlsq`，并导出可以交给其他表格软件查看的 `.xlsx`。

## 产品原则

1. 数据优先。无法识别的格式、旧缓存或未执行的脚本需要可见，不能用看似正常的结果掩盖损失。
2. 表格操作与代码互通。鼠标编辑、粘贴和操作脚本经过同一个事务入口，具有一致的验证与撤销行为。
3. 文档可携带。JS 源码、公式绑定和数据随 `.xlsq` 保存；用户的授权、路径、令牌不随文档传播。
4. 本地运行。基础编辑、计算和保存不依赖网络服务或账号。
5. 兼容性按功能声明。文件能打开、公式能计算、格式能保留是不同承诺。

## 主要使用流程

| 场景         | 用户动作                                 | 成功条件                                                   |
| ------------ | ---------------------------------------- | ---------------------------------------------------------- |
| 业务报价     | 导入商品表，注册折扣函数，修改数量       | 依赖金额正确更新，脚本与公式可以重新打开继续使用           |
| 数据清洗     | 选择区域，执行去空格或规范文本的操作脚本 | 批量修改整体提交，一次撤销完整恢复                         |
| 共享结果     | 将计算完成的工作簿导出为 XLSX            | 导出模式明确，数据类型和已支持格式保留，无隐藏脚本执行要求 |
| 接收他人文件 | 打开 XLSQ，查看数据、代码与缓存状态      | 默认不执行脚本；启用前可查看代码与执行能力                 |
| 大表编辑     | 打开稀疏表格、滚动、粘贴、局部重算       | 内存随实际内容与可见区域增长，长任务可取消                 |
| 多文档工作   | 同时打开两个定义同名函数的文档           | 脚本、撤销、活动工作表和计算结果互不污染                   |

## 桌面交互

主窗口保持“工作簿表格＋公式栏＋脚本侧栏(可收起)”。文件操作、编辑命令与脚本命令可通过菜单、快捷键和可访问名称触发。实现多文档后，每个标签拥有自己的选区、活动表、脚本状态和撤销栈。

> 保持界面紧凑简介，减少文字，不要多余的文案。图形按钮必须有Tooltip，鼠标悬停时显示。

公式栏显示原始输入，单元格显示格式化结果。错误单元格能够打开诊断面板，定位公式、脚本文件和行号。脚本编辑区提供缩进、语法着色、错误标记和函数签名；选用编辑控件前检查许可证与部署成本。

计算状态至少区分：最新、待重算、运行中、已取消、脚本未启用、计算失败、导入缓存未知。显示旧值时必须有状态提示。仅使用颜色不足以表示错误或过期，要提供文本和可访问说明。

打开 XLSX 后默认成为可编辑的导入文档，主保存格式为 XLSQ。导出 XLSX 使用独立动作，不把当前文档悄然改成无法携带脚本的格式。保存文件和启用脚本分别是独立操作。

## 产品验收用例

1. 含文本 `00123`、数字 `123`、空白、空字符串、布尔、日期和错误的表格，经保存、重开、导出后仍能区分。
2. `报价!E2` 调用 JS 函数，`汇总!B2` 引用 `报价!E2`；修改输入后两处更新，旧计算结果不能覆盖新编辑。
3. 操作脚本处理选区后提交 1,000 格变化；一格非法则全部不变，成功后一次撤销恢复原内容、类型与缓存。
4. 打开外来 XLSQ 不运行顶层 JS；停用脚本后仍能查看数据，过期缓存有明确标识。
5. 计算期间保存与关闭有确定顺序；故障后原文件可用，恢复草稿与正式保存文件可区分。
6. 使用他人机器打开发布包，不需要 C++ 编译器；缺失运行时或依赖时能定位问题。

这些用例同时决定测试优先级，不以功能数量替代正确性。
