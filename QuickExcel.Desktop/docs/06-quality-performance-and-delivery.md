# 06 · 质量、性能与交付

本章定义 QuickExcel 从 0.1 原型到 Beta 的验证方法和放行条件。基线日期为 2026-10-22。
“当前证据”仅描述已存在的代码、用例或已有运行记录；“目标”与性能预算都是待实现、待测量的要求。
本轮为文档工作，没有重新执行构建、测试或性能测量。

相关设计见 [系统架构](02-system-architecture.md)、[文件格式](03-file-format-and-compatibility.md)、[脚本运行时](04-scripting-and-runtime.md)及[实施计划](05-implementation-plan.md)。
单元格以独立、稀疏、带类型的领域模型为目标，ExcelIO 是存储适配器；计算只保留一个领域调度器。
XLSQ v2 的单元格权威数据仍在内嵌 `workbook.xlsx`，`state/document.json` 保存补充元数据，测试不得制造两套单元格真源。

此前开发机曾记录 10,000 次简单 JS 调用约 **139 ms**；这是单次原型样本，硬件与预热口径未形成发布基线，本轮未复测。
当前 Core.Test 禁用并行执行；解除全局状态依赖、提供独立测试目录之后，才逐组启用并行。

当前资源限制可从 [WorkbookDocument.cs](../../QuickExcel.Core/WorkbookDocument.cs)、[DocumentPackage.cs](../../QuickExcel.Core/DocumentPackage.cs) 和 [native/SOURCES.md](../../QuickExcel.Scripting/native/SOURCES.md) 核查：

- Core：100,000 行、1,024 列、1,000,000 个计入限制的单元格；当前稠密列表会把部分空洞计入容量。
- UI：100,000 行 × 256 列；单次粘贴 20,000 格；模型允许的列数不等于界面可见列数。
- 文件：输入/输出 64 MiB，ZIP 声明展开总量 256 MiB；XLSQ 外层最多 16 项，内嵌 XLSX 最多 2,048 项。
- 脚本：源码 1 MiB；QuickJS 分配上限 64 MiB、JS 栈 256 KiB、每次载入或调用约 1 秒中断期限。
- 原型重算有约 5 秒的检查预算；这不是操作系统保证的硬截止，必须通过未来 worker 终止机制补强。

## 2. 测试分层与判定原则

以可验证的用户结果和领域不变量为断言对象，避免只镜像实现、只检查“没有抛异常”。
大部分用例不启动 GUI；真实文件、原生运行时及交互链路使用少量高价值集成用例。

| 层次 | 测试对象 | 必须验证的结果 |
| --- | --- | --- |
| 领域单元测试 | 稀疏存储、类型、命令、历史、会话修订 | 状态与历史一致，失败不留下半次编辑 |
| 计算契约测试 | 解析/语义组件、依赖图、统一调度器、缓存状态 | 值、类型、错误、依赖顺序及结果适用版本均正确 |
| 格式集成测试 | XLSX 适配器、XLSQ 包、迁移、导出 | 按兼容性矩阵逐项保真，损失有报告，源文档未被改变 |
| 运行时集成测试 | 真正的 QuickJS DLL、IPC、worker 生命周期 | 有界执行、可取消、错误可解释、故障不损害主进程 |
| UI 契约与端到端 | ViewModel/命令接口及少量真实 WPF 操作 | 编辑提交、焦点、撤销、保存与用户可见状态一致 |
| 发布验收 | 最终目录/安装包、干净 Windows 用户环境 | 安装、启动、保存、升级和卸载行为与说明一致 |

生成式测试使用固定随机种子，失败输出最小重现及种子；快照测试必须说明哪些字段需要比较。
数值断言按函数语义选择精确相等或约定误差，不能用统一宽松误差掩盖文本/数值转换错误。
格式断言检查 XML 类型与地址，而非仅经同一个读写实现往返后比较字符串。
所有缺陷优先补最小回归用例，再修正实现；不为低风险文案修改增加无意义测试。

## 3. 领域、命令与会话质量门禁

**QA-DOM-01：稀疏领域模型。** 用固定坐标集合比较插入、覆盖、删除与枚举，空白位置不创建实体。
在 A1、较远行列和多工作表间交错编辑；模型内存应随实际单元格数量增长，而非随最大坐标矩形增长。
覆盖空工作簿、仅样式单元格、空字符串、删除最后一个值、范围遍历及超出产品容量的明确拒绝。
门禁：模型不变量与随机命令序列通过；已有稀疏坐标回归继续通过。

**QA-CMD-01：命令事务与撤销。** 一次粘贴、清空、填充或脚本批量操作应成为一个可撤销事务。
测试第一个、中间、最后一个单元格验证失败，容量超限，以及提交中抛错；值、类型、公式、缓存、样式和历史必须一起回滚。
Undo/Redo 保存足够的前后状态；停用 JS 时撤销公式编辑，也必须恢复其原缓存及缓存状态。
新增工作表、重命名、删除等操作纳入历史时，还需验证稳定 sheet ID、引用修订和选择位置恢复。
门禁：事务任一点失败都不能产生“文档变了但 dirty 为 false”或“历史记录缺失”的状态。

**QA-SES-01：会话与过期结果。** 用可控制的假调度器安排 A 请求慢于 B 请求返回，不使用 sleep 猜测竞争窗口。
分别修改单元格、脚本、工作表结构，再切换/关闭/重开文档，验证旧结果不会写入新状态。
结果匹配使用运行时文档的完整六元组 `(sessionId, workerInstanceId, requestId, revision, calculationGeneration, scriptGeneration)`。
另测输入 `revision` 不变时连续两轮重算倒序返回：后一轮计算代次发布后，前一轮必须被拒绝。
文件的 `scriptRevision` / `bindingRevision` 不能替代会话 `scriptGeneration`；非计算请求的代次空值按协议严格匹配，不作通配。
取消后到达的成功结果也必须丢弃；拒绝过期结果不应把当前文档误标为已计算或已保存。
门禁：所有确定性乱序场景通过，事件订阅与会话资源随文档关闭释放。

**QA-UI-01：提交契约。** 保留现有“正在编辑 DataGrid 时保存”的回归，并扩展公式栏、IME 组合输入、Tab/Enter、切表及关闭。
保存应先完成有效编辑提交，再等待适用版本的计算/快照策略；失败必须保留用户输入并给出可恢复状态。
撤销快捷键应作用于当前编辑区；脚本编辑器文本历史与表格命令历史不能串用。
门禁：Ctrl+S、另存为、关闭后保存、取消关闭、切表、打开新文档六条链路产生同一正确状态。

**QA-UI-02：基础编辑与结构呈现。** 覆盖选区、当前表、整个工作簿的查找范围，分别验证显示值与公式源码搜索，以及隐藏行参与策略。
“全部替换”必须先验证全部变更，以一个事务提交并一次撤销；非法替换、取消和容量失败均不得留下部分修改。
排序测试包括区域内外及跨表引用、相对/绝对/混合引用、同键稳定顺序、空白/错误值与合并区域冲突，按明确的排序语义断言。
筛选后的复制、粘贴、删除、排序分别验证隐藏行是否参与；不能把视图中的连续位置误当成领域中的连续行号。
行列插入、删除和移动需同步更新公式引用、合并区、图片锚点及选区；跨越边界、合并冲突和撤销/重做都检查完整状态。
基础图片展示验证支持格式、缩放、滚动/冻结下的定位，再保存重开核对图片内容与受支持锚点；复杂锚点按兼容报告处理。
门禁：查找替换、排序筛选、结构编辑与图片展示各有领域断言和关键 WPF 集成场景；失败无部分写入，保存重开后语义一致。

## 4. 类型与文件兼容性测试

**QA-TYP-01：单元格类型矩阵。** 为每种类型建立“编辑→计算→XLSQ→XLSX→重新导入”的预期表。

| 输入/存储情况 | 必须区分和断言 |
| --- | --- |
| 空单元格、空字符串、仅样式单元格 | 缺失值不自动变成数字 0；空字符串不丢失其文本语义 |
| `00123`、以 `=` 开头的文字、前导撇号 | 文本身份保持，编辑表示与存储值可逆 |
| 数字、小数、负数、科学计数、布尔值 | 类型保持；超出约定精度时不静默当成精确数值 |
| 日期、日期时间、仅时间、持续时间 | 数值、格式、日期系统的组合保真，不按操作系统区域性猜测 |
| Excel 错误与文字 `#VALUE!` | 错误类型与普通文字区分，传播符合函数语义 |
| 公式、有效缓存、过期缓存、缺失缓存 | 公式与显示结果分离，过期状态不会被保存流程伪装成有效 |

1900 日期系统单独测试序列 59、60、61；序列 60 的兼容表示遵循格式文档，不强行构造真实的 1900-02-29。
1904 系统测试序列 0、1 及同一实际日期的跨系统转换，避免只改 workbook 标志而不换算值。
另测日期小数部分、负序列的产品策略、夏令时边界；普通 Excel 日期不能被无意转换为本地时区时间戳。
测试 `zh-CN`、`en-US`、`de-DE` 的解析与显示分离，并断言调用完成后线程文化设置已恢复。
门禁：类型往返表全部有自动断言；格式 XML 中的类型和日期系统由独立检查器核实。

**QA-FMT-01：XLSX 与 XLSQ。** 组合覆盖 shared/inline strings、稀疏行列、关系顺序、样式、合并和支持范围内的图片。
按 compatibility matrix 分别判定保留、转换、仅保留但不能编辑、拒绝；不能以“文件能打开”替代保真验收。
XLSQ v1→v2 迁移检查单元格仍由 `workbook.xlsx` 提供，补充状态不覆盖不同版本的单元格数据。
移除 `state/document.json`、损坏其引用、替换内嵌工作簿、伪造版本组合时，必须按明确策略拒绝或降级并报告。
已支持的旧文件不能因添加可选字段而失败；未知必需版本不能被悄悄重写成当前版本。
导出结果快照时验证所有公式消失、类型按策略保留、源文档公式/脚本/dirty 状态不受污染。
将“保留可移植公式”作为未来导出模式时，另建跨软件重算用例，不更改当前结果快照的既有契约。
门禁：已批准的黄金样本按语义比较通过；损失报告列出确切特性与单元格/工作表位置。

**QA-ZIP-01：资源与异常输入。** 外层 XLSQ 与内层 XLSX 分别测试条目数、实际读取字节、单项大小及累计展开量。
覆盖重复名称、大小写/斜杠变体、`..`、绝对路径、超长路径、损坏 CRC、截断包、畸形 XML、DTD/外部实体和巨大共享字符串。
覆盖谎报长度、高压缩比、嵌套包放大、越界/倒序/重复坐标、极远稀疏单元格、海量合并区及巨大图片声明尺寸。
读取预算应在流消费过程中累加；仅检查 ZIP 元数据不能作为完整防护证据。
当前不把条目解压成任意文件；未来增加解压时，测试最终规范化路径始终处于受控目录内。
门禁：所有恶意样本有限时间内终止，工作文档未变化，无目录外文件写入，错误不暴露不必要的完整内容。

## 5. 计算、脚本与故障隔离测试

**QA-CALC-01：单一调度器。** 同一套领域测试驱动普通公式与 JS 函数，防止 UI、Core、Formula 各自维护重算规则。
覆盖链、菱形依赖、重复引用、范围依赖、无界范围按已使用区求值、空引用、错误传播和环下游。
跨表测试包括正序/逆序依赖、三表链、跨表环、带空格/转义名称、重命名、删除表与稳定 ID 重新绑定。
纯标准确定性公式工作簿的局部重算需同时验证结果正确与无关节点没有执行；使用可观测函数计数，不只比较耗时。
含 JS 工作簿在严格策略验证前按保守路径每轮重建上下文并完整重算，测试 UDF 与下游不会误用旧结果；不将任意非确定 JS 纳入增量/全量等价承诺。
缓存被保留时必须标出过期或不可计算原因；未知函数不能悄悄按旧值继续显示为有效。
门禁：跨表结果不依赖工作表排列；统一调度器结果与独立参考求值器在批准语法子集内一致。

**QA-JS-01：真实原生桥接。** 保留现有标量、数组、中文、大小写、非法注册、异常、Promise/对象拒绝用例。
补充重复注册、NaN/Infinity、大整数策略、空值、嵌套/超限参数、错误文本上限及注册后不可变语义。
脚本修改、注册失败、超时或内存耗尽后按策略停用/重建，都要验证函数表与界面状态一致，新会话可恢复正常调用。
原型的同会话中断恢复测试仅作为底层回归；目标 worker 超时/强制终止后的句柄复用规则以运行时文档为准。
测试不同文档之间函数与全局变量隔离；重复创建/释放及调用/关闭竞争不能泄漏句柄或崩溃。
门禁：真实 DLL 集成通过；mock 仅验证上层协议，不能替代原生运行测试。

**QA-WRK-01：worker 取消与崩溃。** 目标为独立进程执行 QuickJS；原型当前仍在主进程内，不具备这项保证。
测试无限循环、递归、巨大分配、长时间 native 运算、卡在 IPC、输出洪泛、主动退出和受控 native crash。
先发送合作取消，超过宽限期终止 worker；主窗口仍响应，主进程内未保存编辑仍可继续编辑和保存，旧 worker 的回复不能再提交。
崩溃后明确标记本次计算失败，允许用户重建 worker；禁止无限自动重启和静默重复运行有副作用的操作。
协议测试包含截断消息、长度溢出、无效类型、未知版本、重复 request ID 和不属于当前 session 的响应。
门禁：全部故障留在 worker 边界内，主进程没有退出，事务没有部分提交，重建后健康工作负载可通过。

**QA-OS-01：受限执行能力。** “没有 JS 文件 API”与“操作系统限制生效”分别取证。
M4 交付 OS 隔离策略原型与机制选择证据；本项完整门禁在 M6 放行，不能因独立 worker 已运行就提前关闭。
在未来选定的受限 token/AppContainer、Job Object、IPC ACL 等机制下，从 worker 原生测试钩子尝试访问真实资源。
覆盖读写用户文档/凭据目录、网络连接、创建子进程、继承句柄及越权连接其他文档 IPC 通道。
允许资源按清单逐项测试；默认不授予文件系统和网络权限，临时资源只能访问当前任务授权范围。
安装/开发模式不能静默绕过限制；缺少必需限制时应拒绝启用脚本并说明原因。
门禁：禁止项被 OS 拒绝且有可重复证据；完成前不得宣传“安全执行任意不可信脚本”。
OS 门禁未通过时只可提供明确限定可信脚本的试用候选，不计为 M6 Beta 完成。

## 6. 保存、恢复与隐私

**QA-SAVE-01：故障注入。** 当前同目录临时文件、flush、replace/move 是基础，不等于已验证断电恢复。
M2 验证序列化与原子替换的基础失败路径；外部冲突、写后校验及完整故障矩阵随 M6 的 FMT-010 最终验收。
在序列化、临时写入、flush、目标替换前后分别注入异常、磁盘满、权限拒绝、目标占用和进程终止。
已有文件的成功内容必须仍能读取；新文件保存失败不得把半成品当成成功；dirty 与保存修订只有成功提交后更新。
另测外部进程修改文件、只读目录、长/中文路径、移动后的文档和同步盘冲突，不能无提示覆盖别人的新版本。
在隔离 VM 做进程强杀和文件系统故障测试；“断电保证”只有经目标文件系统与恢复流程验证后才能声明。
门禁：重启后文件是前一完整版本或后一完整版本；无法恢复时保留证据，不自动覆盖唯一可用副本。

**QA-REC-01：恢复副本。** 目标恢复记录以文档 ID、修订和写入完成标记关联，不以文件名判断唯一性。
自动保存与恢复后端属于 M6（FMT-010）；M5 可验证恢复 UI 原型，但不能据此关闭完整恢复门禁。
覆盖应用崩溃、脚本 worker 崩溃、保存失败、恢复日志截断、旧版本升级及两个实例同时编辑。
恢复只重建数据与源码，绝不自动启用脚本；用户可预览、另存或丢弃，原文件保持可选择。
测试保留期、清理、磁盘预算与显式删除；恢复能力不能无限占用磁盘。
提议目标：dirty 文档每 30 秒请求一次一致快照，连续编辑也必须触发，不能无限等待输入空闲。
在磁盘正常可写且满足已批准工作负载的条件下，已提交命令的未持久化窗口 p95 ≤ 60 秒；计时从命令提交到含该命令的恢复快照完整持久化。
超过 60 秒时显示恢复滞后状态；失败应限频重试并持续提示，不能静默停用或通过重置计时隐藏延迟。
使用可控时钟验证触发、连续编辑、失败和重试，再以真实磁盘与批准负载测量窗口；超出适用条件仍须准确显示滞后和失败。
这些数值尚未达成，M6 实测后冻结目标与负载口径；调整必须记录依据，不能把原型能力描述为已满足该窗口。
门禁：恢复结果有来源与时间，损失窗口可测量并展示，所有删除均遵循已定义的保留规则。

**QA-PRIV-01：默认本地。** 工作簿、脚本、单元格值、文件路径和剪贴板内容不自动上传。
M4 验证已交付的运行时与文档流程；新增的自动保存、恢复和诊断路径在 M6 复验后完成整项门禁。
使用阻断外网环境验证编辑、保存、重算和恢复；监测连接行为，区分构建阶段下载源码与运行阶段处理用户文档。
默认日志只记录代码、耗时、版本及计数；异常消息可能含用户内容，写入诊断包前需过滤或明确用户选择。
崩溃 dump 默认不收集/上传；若用户主动导出诊断，先展示范围并允许排除文档与脚本。
门禁：默认运行无内容出站流量，日志样本不含植入的敏感标记，诊断导出行为可撤销且可检查。

## 7. 性能工作负载与提议预算

本节数值全部是 **Beta 提议目标，尚非实测结果或承诺**；先建立 M1 基线，再根据实际瓶颈调整并记录理由。
不能将当前 64 MiB QuickJS 堆限制解释为整应用内存，也不能将当前 5 秒检查解释为硬实时保障。

提议固定基准机 `QX-B01`：Intel Core i5-12400、6 核 12 线程、16 GiB DDR4-3200、NVMe SSD、Windows 11 x64。
使用固定系统镜像；镜像 SHA-256、Windows build、BIOS、电源模式、显示缩放、SDK/CLR、编译器和应用提交写入基线清单。
基线清单未锁定前只允许探索性测量，不发布比较结论；同一序列禁止混用物理机与虚拟机结果。
Release x64、不附加调试器；冷启动与热运行分开；固定数据种子与脚本源码，不把杀毒关闭作为正常使用前提。
端到端样本至少 30 次；稳态调用预热后分批记录；输出原始样本、p50/p95、峰值 private bytes、CPU 与 GC 数据。

| 工作负载 | 固定内容与测量起止点 | 提议目标 |
| --- | --- | --- |
| P01 启动 | 空文档，进程启动→可键盘编辑；另记冷/热缓存 | 热启动 p95 ≤ 1.5 s，冷启动 p95 ≤ 3 s |
| P02 交互 | 100,000 实际单元格、10,000 行×10 列；输入/滚动事件→下一帧 | 输入反馈 p95 ≤ 50 ms，滚动帧 p95 ≤ 33 ms |
| P03 稀疏 | 20,000 实际单元格分散到 100,000 行×1,024 列，固定坐标种子 | 领域模型增量内存 ≤ 64 MiB，不实例化空矩形 |
| P04 文件 | 10 MiB 压缩 XLSX、100,000 单元格、10,000 公式、20 共享样式、无图片 | 打开至可编辑 p95 ≤ 3 s；XLSQ 保存 p95 ≤ 2 s |
| P05 原生公式 | 10,000 个非循环节点，链/菱形/范围各占约三分之一 | 全量 p95 ≤ 500 ms；影响 1,000 节点的增量 p95 ≤ 100 ms |
| P06 JS 桥接 | 10,000 次两数字参数、标量返回；另列 worker 批量与逐次 IPC | 批量端到端 p95 ≤ 500 ms，不套用原型 139 ms 样本 |
| P07 取消 | 无限循环任务，用户点击取消→worker 终止/结果作废可见 | UI 反馈 ≤ 100 ms，任务终止 p95 ≤ 1.5 s |
| P08 会话寿命 | 100 次开关文档，每次启停脚本、编辑、保存，空闲回收后比较 | 无持续线性增长；最后 20 次相对前 20 次中位增量 ≤ 20 MiB |

另建图片、超长文本、海量样式和最大边界压力集，单独报告；不能让普通负载指标掩盖压力集失控。
性能回归提议门槛：同机 p95 相对已批准基线退化超过 15% 且重复两轮复现时阻止发布，除非有审阅记录的预算调整。
所有优化同时跑正确性回归；减少计算、丢弃缓存或跳过文件内容造成的“提速”不能算合格。
**QA-PERF-01 门禁：** 工作负载生成器、基线清单、原始结果可复现，Beta 达到批准后的预算且没有未解释的内存增长。

## 8. CI 与源码构建矩阵

**QA-CI-01：Windows x64 是当前交付矩阵的必选项。** 不把 WPF 标为跨平台，也不要求桌面链路安装 WASM 工作负载。
当前仓库尚无完成的 QuickExcel CI 工作流；下表是要新增的流水线，不是现有自动化能力。

| 触发/环境 | 必跑内容 | 必留产物 |
| --- | --- | --- |
| 每次 PR，固定 Windows x64 镜像 | Release 构建；Core 领域/格式/计算用例；ExcelIO、NetStandard、Formula 回归 | TRX、构建版本、失败最小样本 |
| 涉及脚本/原生代码的 PR | 从固定源码强制重建 DLL；native smoke；Core 真 JS 集成 | 源码 hash、工具链版本、DLL hash、smoke 输出 |
| 涉及 UI 的 PR，交互桌面 runner | ViewModel/命令测试；WPF `--smoke-test`；关键焦点用例 | 进程退出码、结果文本、必要截图 |
| 夜间隔离 VM | ZIP/XML 变异输入、进程终止、保存故障、worker 故障、资源泄漏 | 种子、故障位置、预算与恢复报告 |
| 发布候选，干净 Windows x64 | 完整源码构建→最终发布目录→无 SDK 环境验收 | 最终目录清单、hash、许可证、验收记录 |

独立测试并行使用独立目录；UI 测试不与性能测量共享机器；故障注入只作用于隔离测试目录和测试进程。
现有 `scripts/build.ps1` 包含 Web 路径且未完整覆盖 Formula，不应充当 QuickExcel 唯一门禁。
跨项目回归应明确执行以下项目，结果跳过项单列并有原因，不能把 skipped 计为 passed：

```powershell
dotnet test .\ExcelIO.Test\ExcelIO.Test.csproj -c Release -v minimal
dotnet test .\ExcelIO.NetStandard.Test\ExcelIO.NetStandard.Test.csproj -c Release -v minimal
dotnet test .\ExcelIO.Formula.Test\ExcelIO.Formula.Test.csproj -c Release -v minimal
dotnet test .\QuickExcel.Core.Test\QuickExcel.Core.Test.csproj -c Release -v minimal
dotnet run --project .\QuickExcel.Scripting\smoke\QuickExcel.Scripting.Smoke.csproj -c Release
```

UI smoke 是 GUI 进程，CI 要等待退出并检查 `ExitCode`，不能启动后立即读取上次留下的文件：

```powershell
dotnet build .\QuickExcel.Desktop\QuickExcel.Desktop.csproj -c Release -v minimal
.\scripts\build-quickexcel.ps1
$qaRun = Join-Path $PWD ("artifacts\qa-" + [Guid]::NewGuid().ToString('N'))
$qaProcess = Start-Process -FilePath .\artifacts\QuickExcel\QuickExcel.exe `
    -ArgumentList @('--smoke-test', ('"' + $qaRun + '"')) -PassThru -Wait -WindowStyle Hidden
if ($qaProcess.ExitCode -ne 0) { throw "WPF smoke failed: $qaRun" }
```

脚本示例仅说明未来自动化入口；正式 CI 应加任务超时并同时校验新生成的 `smoke-result.txt`，截图仅作辅助证据。
需要真实交互桌面的测试不得通过无 GUI 服务环境的“进程能启动”冒充通过。

## 9. 原生来源与发布验收

**QA-SUP-01：固定来源。** 当前来源是 QuickJS-NG 0.17.0；压缩包 SHA-256 固定为：
`9DE1BF573606D2AEBBBAB6217E616A66E09E3613518489B37B9B3157CF398DCC`。
详见 [SOURCES.md](../../QuickExcel.Scripting/native/SOURCES.md) 与 [build.ps1](../../QuickExcel.Scripting/native/build.ps1)。
普通构建只在 DLL 缺失时生成，不能据此证明本次 native 源码已进入二进制；CI 从干净 vendor/build 目录重建。
缓存键包含源码 hash、桥接源码 hash、CMake 配置、MSVC 版本和架构；不复用来源不明的已有 DLL。
发布清单记录源码/产物 hash、依赖及 MIT 许可证；变更引擎版本后重新执行全部运行时和故障用例。
门禁：包内 `quickexcel-js.dll` 与本次构建记录匹配，来源可追溯，必要许可证齐全。

**QA-REL-01：完整包验收。** 当前 `--self-contained false` 发布依赖 .NET 10 Windows Desktop Runtime。
最终包必须同时包含托管程序、原生 DLL、许可证和必要配置；复制单个 exe 不属于受支持分发方式。
在无 SDK、无 Visual Studio、无 CMake 的干净标准用户环境测试；仅安装声明的 Desktop Runtime 后应可完整运行。
缺失/错误架构 DLL、缺失 Runtime、无写权限和非 ASCII 路径应给出可理解错误，不破坏用户文件。
后续若采用 self-contained，另测更大的包、补丁更新与 Runtime 安全维护，不混淆两种交付模式。
Beta 前建立带 hash 的版本 ZIP；Windows 可执行文件/DLL 与安装器签名纳入发布阶段，ZIP 另附签名清单。
升级/回滚测试覆盖文件关联、用户设置、恢复副本和新旧格式；卸载不能删除用户工作簿。
门禁：最终下载包在干净机器上跑完打开→编辑→JS→保存→重开→导出流程，签名/清单和发布说明一致。
