# 文件格式与兼容性设计

[返回文档索引](README.md) · [系统架构](02-system-architecture.md) · [脚本运行时](04-scripting-and-runtime.md) · [实施计划](05-implementation-plan.md) · [原型使用说明](../README.md)

本文规定 QuickExcel 的工作簿交换边界、`.xlsq` 演进方向与文件验收标准。
文中的“已实现”来自当前代码；“目标”是后续实现合同；“延期”表示不属于近期兼容承诺。
以下 v2 结构是设计提案，当前应用仍只读写 v1，不能直接读取示例中的 v2 文件。

## 1. 决策与职责

- `.xlsx` 是传统表格交换格式；`.xlsq` 是包含脚本源码和编辑状态的 QuickExcel 文档。
- `workbook.xlsx` 始终是单元格值、公式、公式缓存值、样式与工作表结构的唯一文件权威来源。
- 补充 JSON 只存稳定标识、脚本绑定、修订与缓存新鲜度、界面状态，不再次存单元格内容。
- 文件打开、预览、迁移与恢复均不得执行 JavaScript；只有用户对当前文档显式启用脚本后才执行。
- 文件不得保存“已经信任”“已经授权”“下次自动运行”等可以改变宿主权限的状态。
- 文件可被读取、公式可被计算、内容可被完整往返是三个独立能力，界面与兼容报告分别说明。

文件服务处理包结构、校验、迁移和原子写入；领域层处理类型与身份；计算服务提供缓存有效性；导出规划器决定公式保留和损失清单。
UI 负责展示结果与选择，不通过直接改 ZIP/XML 绕过命令或修订机制。

## 2. M0 已实现的 `.xlsq` v1

实现入口：[DocumentPackage.cs](../../QuickExcel.Core/DocumentPackage.cs)、[WorkbookDocument.cs](../../QuickExcel.Core/WorkbookDocument.cs)。
现有包正好写出三个条目：

```text
报价单.xlsq
├── manifest.json
├── workbook.xlsx
└── scripts/functions.js
```

当前写入代码产生的 manifest 内容如下，属性值不是占位示例：

```json
{
  "format": "QuickExcel",
  "formatVersion": 1,
  "scriptApiVersion": 1,
  "workbook": "workbook.xlsx",
  "script": "scripts/functions.js"
}
```

已实现的行为：

| 能力 | 当前实际行为 |
| --- | --- |
| 版本读取 | `formatVersion` 必须为整数 1；存在 `format` 时必须为 `QuickExcel` |
| 位置解析 | 按固定路径读取工作簿与脚本；尚未把 manifest 中的路径作为可变入口 |
| 脚本内容 | 严格 UTF-8 源码；没有字节码、模块图、权限清单 |
| 文档打开 | 脚本默认停用；加载公式及已有缓存，不主动执行源码 |
| 文档保存 | 克隆工作簿后序列化；保存公式、缓存、受支持样式和脚本源码 |
| XLSX 导出 | 克隆工作簿，将所有公式替换为当前缓存文本；不改动原文档 |
| 稀疏坐标 | 在 ExcelIO 读取后按原始 `r` 地址恢复空列，避免 B1 被移到 A1 |
| 原子替换 | 同目录临时文件，刷新后替换已有目标；失败时清理临时文件 |
| 缓存状态 | 没有持久化新鲜度、计算修订或脚本修订标记 |

当前 `scriptApiVersion` 未作为严格读取门槛，未来读取器必须补齐版本检查。
原型遇到停用的自定义函数或跨表公式时保留缓存并给出诊断；这些缓存不因此获得“最新”的保证。
原型导出全部使用当前结果，不能声称“保持 Excel 原公式”。

## 3. M0 容量与兼容限制

以下是当前实现的限制，不是 `.xlsq` 格式永久允许的最大尺寸：

| 项目 | 当前上限或行为 |
| --- | --- |
| 输入文件与写出文件 | 64 MiB |
| 外层 ZIP | 最多 16 个条目；单条目 64 MiB；声明展开总量 256 MiB |
| 内嵌 XLSX | 最多 2048 个条目；单条目 64 MiB；声明展开总量 256 MiB |
| manifest / 脚本源码 | 64 KiB / 1 MiB |
| 解析工作表 | 最多 64 张；每表最多 100,000 行、1,024 列 |
| 分配单元格 | 工作簿最多 1,000,000 格，计入稀疏行恢复所需空格 |
| 桌面显示编辑 | 每表最多 100,000 行、256 列；界面上限与文件模型上限不同 |
| XML 预检 | 禁止 DTD，禁用外部解析器，单文档字符数有限制 |
| 非标准布局 | 缺少行地址、乱序或重复地址等会被当前严格预检拒绝 |

读取会检查 ZIP 重名条目和容量；脚本与内嵌工作簿复制过程也检查实际读取量。
尚不能把这些措施描述成完整的恶意文件防护：全局累计分配预算、所有关系路径规范化与隔离读取仍需 M2 完成。
当前单元格模型以字符串为主，导出的字面值沿用文本类型；数值、布尔、错误和日期的类型保真尚未完成。
完整限制见[原型说明](../README.md)，测试基线见[WorkbookDocumentTests.cs](../../QuickExcel.Core.Test/WorkbookDocumentTests.cs)。

## 4. 目标 v2 包结构

v2 仍采用 ZIP 外壳与内嵌 XLSX，避免形成第二套工作表序列化格式。
以下路径是 v2 的规范路径；模块文件名由内容映射声明，不由磁盘目录搜索推断。

```text
报价单.xlsq
├── manifest.json
├── workbook.xlsx
├── state/
│   └── document.json
└── scripts/
    ├── main.js
    └── lib/
        └── pricing.js
```

不得增加 `cells.json`、`formulas.json` 或第二份 `original.xlsx` 来竞争工作簿权威来源。
未知 OpenXML 部件若能保留，应保留在 `workbook.xlsx` 内部；导入时的原始包缓冲属于会话实现细节。
搜索索引、缩略图和诊断日志为可重建内容，首版 v2 不写入；未来增加时必须声明为可选缓存。

目标 manifest 示例中的哈希使用占位符；实际文件必须写完整的 64 位小写十六进制 SHA-256 值：

```json
{
  "format": "QuickExcel",
  "formatVersion": 2,
  "minReaderVersion": 2,
  "scriptApiVersion": 1,
  "requiredFeatures": ["typed-workbook", "stable-sheet-ids", "script-modules"],
  "workbook": { "path": "workbook.xlsx", "sha256": "<64 hex digits>" },
  "state": { "path": "state/document.json", "sha256": "<64 hex digits>" },
  "scripts": {
    "entryModules": ["main"],
    "modules": {
      "main": { "path": "scripts/main.js", "sha256": "<64 hex digits>" },
      "pricing": { "path": "scripts/lib/pricing.js", "sha256": "<64 hex digits>" }
    }
  }
}
```

哈希覆盖条目的原始解压字节，不对换行或空白做隐式规范化；manifest 本身不自包含哈希。
哈希用于发现内容不一致和复用计算缓存，不证明作者可信，也不授予执行权限。
写入器只引用实际存在的条目；读取器拒绝缺失、重复、哈希不符和映射到同一条目的歧义模块。

## 5. 目标补充状态模型

以下示例中的 UUID 表示文档与表的稳定身份，修订号表示同一文档内的状态版本：

```json
{
  "documentId": "a048f745-74ca-477b-889b-e2cf88c6f4bf",
  "contentRevision": 42,
  "scriptRevision": 3,
  "bindingRevision": 2,
  "sheets": [
    {
      "id": "11aa3daf-799a-4c2a-b591-6c276b28a691",
      "workbookSheetId": "1",
      "part": "xl/worksheets/sheet1.xml"
    }
  ],
  "scriptBindings": [
    { "module": "main", "scope": "workbook", "kind": "formula-functions" }
  ],
  "calculation": {
    "state": "stale",
    "contentRevision": 41,
    "scriptRevision": 3,
    "bindingRevision": 2,
    "engineVersion": "<implementation version>",
    "scriptSetSha256": "<64 hex digits>"
  },
  "view": {
    "activeSheetId": "11aa3daf-799a-4c2a-b591-6c276b28a691",
    "selection": "B2",
    "zoom": 1.0
  }
}
```

此文件没有 `value`、`formula`、`style` 或另一份工作表名称/顺序列表。
表名、顺序、单元格与缓存内容均从 XLSX 读取；`workbookSheetId` 与 `part` 是身份校验绑定，不是替代工作表定义。
两者必须与工作簿关系解析结果一致；不一致时报告损坏，不按相似表名猜测归属。
重命名与重排保持稳定 ID；复制工作表生成新 ID；删除表同步清理绑定与视图引用。

`contentRevision` 在会影响工作簿内容的命令提交后推进；视图滚动不推进它。
`scriptRevision` 在源码集合变化后推进；`bindingRevision` 在入口与绑定变化后推进。
撤销与重做属于新提交，不把单调修订号倒退；恢复的是内容，缓存通过依赖或内容摘要重新验证。
`calculation.state` 只允许 `unknown`、`fresh`、`stale`、`partial`；缺失一律按 `unknown`。
全局 `fresh` 仅当本次受支持计算全部完成、所需脚本集匹配且所有修订一致时成立。
错误值可以是一次完整计算的合法结果；超时、取消、未知函数和未覆盖的公式语义导致 `partial` 或 `unknown`。
后续可增加按稳定表 ID 和区域记录的新鲜度例外，但仍不得把缓存值复制到 JSON。

## 6. 目标单元格类型与日期约定

类型先在 M1 领域层建立，在 M2 读写器中落实。公式是一项独立表达式，其缓存结果使用同一值类型集合。

| 领域值 | 约定 | XLSX 往返目标 |
| --- | --- | --- |
| `Blank` | 无值；与空文本不同 | 不凭空变成 `0` 或空字符串 |
| `Number` | 有限 `double`；拒绝 NaN 与无穷 | 数值写入数值单元格，使用不变区域性 |
| `Text` | Unicode 字符串，包括 `""`、`"00123"` | 保留文本类型和前导零，不按外观猜数字 |
| `Boolean` | `true` / `false` | 保留布尔类型，不写成文本 TRUE/FALSE |
| `Error` | 结构化错误码与可选宿主诊断 | 标准错误按错误类型写入；宿主错误另作映射 |

用户输入解析、剪贴板解析与文件读取是不同入口，必须使用明确规则。
文件已有类型信息时直接采用，禁止用 `double.TryParse` 重新猜测文本 ID。
单引号转义属于编辑输入语法，不写入用户文本本身；显式空文本也不能被缺失单元格吞掉。
JSON 与 JS 桥接不得把 `Blank`、空文本、错误和布尔值一律变成字符串；桥接规则由脚本规范统一。

日期没有独立的自动 `DateTime` 单元格类型：保存数字序列值、数字格式以及工作簿 1900/1904 日期系统元数据。
相同序列值可按不同格式显示为日期、时间、时长或普通数字；改格式不能改原始数值。
M2 必须覆盖两个日期系统、序列值 59/60/61、负值、小数时间和累计时长格式的导入导出夹具。
兼容性特殊值不得经通用 `DateTime` 转换被静默归一化；日期函数与显示层的完整兼容算法单独验收。
跨日期系统复制时由命令明确选择保留原数值或保留显示日期，并记录可撤销的转换。

## 7. 目标脚本模块与绑定

注册 API 保持 `quickExcel.functions.register("DISCOUNT", fn)`，不因包格式升级改变用户函数写法。
M0 的 `scripts/functions.js` 是单个脚本；M4 才提供受控模块加载器，M2 可先保存和验证模块结构。
模块 ID 是包内逻辑标识；源码 import 只能解析到 manifest 内容映射中的包内模块。
禁止运行时下载模块、读取任意磁盘路径或按当前进程目录查找依赖；不因使用模块机制自动提供 Node.js API。
模块环、缺失模块、重复函数注册与入口顺序都有确定性诊断；整个脚本集验证完成后才替换当前会话。
多个入口按 manifest 顺序装载，但函数注册失败必须整体回滚，不能留下半注册状态。

M2 的基础 v2 只支持工作簿级公式函数绑定；上文的纯公式 manifest 与状态示例保持不变。
M4 的 FMT-008 在同一 `formatVersion: 2` 上增加操作脚本能力：manifest 必须同时声明 `requiredFeatures` 中的 `script-actions` 与 `scriptApiVersion: 2`。
操作绑定采用 `{ "module": "main", "scope": "workbook", "kind": "actions" }`，模块必须已经存在于内容映射并列入 `scripts.entryModules`。
不识别 `script-actions` 的读取器拒绝正常可编辑打开，不能忽略该能力或把动作绑定当作公式入口。
同一模块同时承担公式与动作入口时，注册上下文的隔离或装载相位以[脚本运行时规范](04-scripting-and-runtime.md)为准；文件层不以加载顺序隐式混合两类权限。
动作绑定只描述可由用户显式运行的入口；保存、打开、迁移和恢复仍然不执行源码，也不恢复运行授权。工作表专属作用域继续延期。
内容映射只保存源码位置与摘要，不保存 QuickJS 对象、指针、堆快照、执行栈或引擎字节码。
脚本启用与宿主授权只属于运行会话；复制、恢复、另存为或迁移文件不能复制授权状态。
读取并校验源码不等于执行；缓存预览在脚本未启用时仍然可用，但必须展示其新鲜度。

## 8. 版本策略与 v1 → v2 迁移

`formatVersion` 表示文档结构主版本，`scriptApiVersion` 表示脚本宿主合同；二者独立演进。
兼容的小型扩展使用可选字段，读取器忽略但保存时需保留可安全保留的未知可选字段。
新增能力只要不改变已有字段语义、权威来源或既有执行模型，可在同一主版本中使用 `requiredFeatures` 声明；旧读取器因此明确拒绝，而不是误解文档。
改变已有字段语义、权威来源、必需入口的含义或既有执行模型必须升级主版本，不能偷偷复用原版本。M4 的 `script-actions` 是显式新增入口能力，不重新解释已有公式绑定。
`requiredFeatures` 是完整理解文档所需能力；任何未知必需能力都禁止正常可编辑打开。
v2 读取器严格验证 `format`、版本、必需字段、字段类型和入口，不能沿用 v1 的宽松字段缺省行为。

迁移过程：

1. 按 v1 读取规则校验并加载三项内容，不执行脚本、不修改原文件。
2. 为文档与工作表生成稳定 ID，将原脚本登记为单入口模块，保持源码字节内容。
3. 类型只从内嵌 XLSX 已有类型恢复；无法还原原型已丢失的数值/文本差异，禁止猜测修复。
4. 初始化修订与缓存状态为 `unknown`，原公式和缓存值继续留在 `workbook.xlsx`。
5. 在当前会话标注“已迁移、尚未保存”；用户保存时才原子写出 v2，并保留明确的另存为路径。
6. 迁移与保存后重新读取，核对表身份、源码摘要、公式数量、受支持类型和已声明损失。

读取未来版本时拒绝正常编辑、重存和自动降级，错误应指出所需版本或未知能力。
可以提供独立“提取内嵌工作簿”操作，但必须沿严格固定入口和容量校验，只生成新的 XLSX 文档。
这种提取不宣称理解未来格式，不执行脚本，不覆盖来源，也不把未来状态当作 v2 保存。
回写 v1 不是自动兼容动作；若以后提供降级导出，必须先计算模块、状态与类型损失。

## 9. 目标读取管线与预算

读取必须有统一预算对象，覆盖外层 ZIP、嵌套 XLSX、XML/JSON、字符串池与领域分配。
现有 M0 上限可作为初始配置，但要按所有工作表累计，而非只对每个文件或每张表各自检查。
处理顺序为：文件签名与长度 → 中央目录 → manifest → 条目映射 → 摘要 → XLSX 关系与结构 → 类型化领域快照 → 补充状态绑定。
任一步失败均不替换当前已打开文档；诊断包含条目与原因，不泄露临时路径或内部栈给普通用户。

- 同时限制声明长度和实际解压字节数、条目数、层数、字符串长度、XML 深度、JSON 深度、表数与总分配量。
- 规范化包路径只允许 `/` 分隔的相对路径；拒绝空路径、绝对路径、盘符、反斜线和越界 `..`。
- 在规范化后检查重复路径、等价路径与大小写歧义；不能让一个读取阶段与另一个阶段看到不同条目。
- 不把 ZIP 整包解压到用户目录；若需要缓存，使用宿主私有临时目录并在写前验证最终路径。
- 外层模块路径必须位于 `scripts/` 且出现在内容映射；不推断或执行未声明条目。
- OPC 关系按源部件目录解析，验证内容类型、关系类型、内部目标存在性与允许的结构。
- 外部关系不得联网解析；仅作为不透明关系记录，交由兼容报告决定保留或移除。
- XML 禁用 DTD 与外部实体；JSON 拒绝重复关键属性，限制文本与集合大小。
- 对地址、维度与范围采用溢出检查；不得因伪造远端地址提前分配整个矩形。
- 取消或预算耗尽会终止整个读取，不返回内容不完整却被标成正常的文档。

摘要正确不豁免上述检查；不同实现使用相同规范化和预算测试集。
加密、密码保护容器与修复损坏压缩包延期；错误时不尝试执行脚本“修复”文件。

## 10. 原子保存、自动保存与恢复

已实现：同目录临时写入、刷新、替换目标；原型没有自动保存与恢复日志。
目标保存从一个不可变 `DocumentSnapshot` 开始，捕获内容、脚本、绑定和计算修订，不与正在编辑的对象交错序列化。
写入后先重开校验结构、摘要、必需部件与修订一致性，再提交最终替换。
目标文件若在加载后被外部进程修改，应报告冲突并保留另存为选择，不默认覆盖更新内容。
替换成功才推进“已保存修订”；若写盘期间用户继续编辑，窗口仍保持未保存状态。
临时文件、备份与自动保存文件都使用不同角色，不能把上次成功保存误当作可随时清理的缓存。

自动保存是 M6 的恢复机制：保存到应用恢复目录，关联文档 ID、来源路径、基础文件摘要和快照修订。
自动保存不覆盖用户文件、不把文档标记为已保存、不执行脚本、不持久化授权。
恢复频率的初始提议为：文档变为 dirty 后，每 30 秒请求一次一致快照；计时不能因后续编辑不断重置，连续编辑同样触发。
在磁盘正常可写且负载位于已批准范围内时，已提交命令尚未进入成功提交恢复快照的时间窗口目标为 p95 ≤ 60 秒；这不包含尚未提交的编辑控件输入。
存在已提交命令超过 60 秒仍未被成功提交的恢复快照覆盖时，界面显示“恢复滞后”；失败重试必须限频并给出持续可见的警告，不能高频重试阻塞编辑或掩盖失败。
这些数值是 M6 待测量的初始预算，固定机器、磁盘与工作负载后再冻结验收标准；异常关闭仍可能丢失最近尚未落盘的操作，不承诺零损失。
崩溃恢复先列出候选与修订，读取方式与普通不可信文件相同；恢复后作为未保存的新会话打开。
恢复快照必须完整提交，禁止只恢复一半脚本、一半工作簿；旧候选在新快照提交后才按策略清理。
异常退出、磁盘满、目标锁定、断电窗口与恢复目录损坏均应有故障注入测试。
文件系统不能提供所需替换保证时，保存失败需明确报告，不能冒充原子成功。

“目标支持”均需通过 M2/M3 的夹具验收后才能进入对外承诺；本表不表示当前已经具备。

| 内容 | M0 已实现 | 目标 | 延期或限制 |
| --- | --- | --- | --- |

## 12. 目标导出策略与依赖闭包

提供两个明确导出模式；导出始终生成副本，不修改原 `.xlsq` 的公式、缓存或脚本。
“当前结果快照”把所有公式变成类型化缓存值；这是 M0 的现有方向，M2 补类型与新鲜度检查。
“保留兼容公式”在 M3 提供：保留经过支持矩阵确认的标准公式，冻结不可在目标环境计算的内容。

保留公式模式按以下步骤建立可审阅的 `ExportPlan`：

1. 在冻结的同一文档修订上分类普通公式、含 JS 的公式、未知公式与外部引用。
2. 任一公式调用 JS，无论嵌套在 `IF`、`SUM` 或其他表达式中，都将整个单元格列为快照种子。
3. 默认把种子的全部传递依赖者一并冻结，包括跨表依赖，避免用户以为导出后修改输入仍会重新执行 JS。
4. 未受影响且语义被支持的标准公式保留为公式；其缓存与输入值按类型写出。
5. 依赖不可完整解析时采用保守影响范围；不能证明独立的公式不得被标为“可继续完整重算”。
6. 只有缓存可用且在当前修订上新鲜，才进入正常快照导出；缺失缓存阻止导出该计划。
7. 过期缓存可以通过明确的“导出已有结果”选择使用，报告包含过期格数与原因；不隐式启用脚本补算。

导出报告至少列出保留公式数、冻结公式数、未知依赖、过期或缺失缓存，以及被移除的部件。
未知标准公式若原样保留给 Excel，必须满足无失效编辑、关系仍有效和报告标记“本应用未验证重算”。
宿主专用错误如 `#SCRIPT!` 与 `#CYCLE!` 不能直接冒充标准 Excel 错误码；导出器选择约定标准错误或明确文本，并在报告中记录。
未来可提供“只冻结 JS 种子、保留其标准公式依赖者”的高级模式，但必须说明修改输入后 JS 输出仍固定；首个保真版本延期此选项。

## 13. 未知 OpenXML 部件保留规则

当前模型重建 XLSX，不提供任意未知部件原样往返承诺。M2 引入部件目录、关系图和保留判定。
“不透明保留”仅表示原始内容与关系被留存，不表示可以理解、显示、计算或编辑。
无编辑保存应优先保持原部件内容；涉及未知特性的文件必须能说明哪些部件仍然可信。

| 编辑类型 | 保留判定 |
| --- | --- |
| 仅选择、滚动、缩放或更改脚本源码 | 不改变 XLSX 内容，原则上可以保留原有部件 |
| 已知单元格内容或样式修改 | 仅在证明未知部件不引用该内容且不存在隐式依赖时保留 |
| 插入/删除行列、重命名/删除/复制工作表 | 可能影响地址、关系和定义；未知依赖不能证明安全时判为失效 |
| 删除图片、合并或更改锚点 | 与受影响关系链有关的未知部件需重新判定 |
| 未知部件内部定义了无法解析的依赖 | 保守判定相关数据编辑可能失效，不靠原样复制宣称无损 |

失效时在保存/导出前给出具体损失和选项：取消、另存为受支持子集，或保留原文件继续处理。
禁止静默删除，也禁止保留已知失效引用后宣称成功兼容。
不透明部件应与其内容类型和关系一起处理；清除部件时同步清理悬空关系，但不能误删共享部件。
这项能力只在能验证不发生失效的情况下减少损失，不承诺通用 Excel 文件无损编辑。

## 15. 验收夹具与失败标准

- FMT-001：同一 v1 示例多次保存/打开后源码字节、公式与缓存一致；打开含抛错源码的文件仍成功且没有执行。
- FMT-002：工作表重命名、重排、复制、撤销后身份正确；快照不混用不同内容与脚本修订。
- FMT-003：v1 升级保留可恢复信息；未来主版本、未知必需能力、错类型字段及缺失入口均拒绝正常编辑。
- FMT-004：`00123` 文本、空文本、Blank、布尔、标准错误、有限数值、日期系统和稀疏远端格逐项语义往返。
- FMT-005：重复/歧义路径、目录穿越、压缩炸弹、实体展开、超深 JSON、关系环或缺失目标均有确定诊断；内存不越过配置预算。
- FMT-006：无失效编辑保留被支持的不透明部件；破坏其依赖的编辑必有损失报告，不能产生无提示的悬空关系。
- FMT-007：跨表 JS 种子及传递依赖全部进入默认快照闭包；不相关标准公式保留；过期缓存不得伪装新鲜。
- FMT-008：缺失模块、摘要不符、重复注册和循环加载按规范处理；动作源码及 `actions` 绑定保存重开后完整保留；缺少 `script-actions`/API v2、非工作簿作用域或绑定未声明入口均被拒绝；旧读取器拒绝未知必需能力；保存、打开、迁移、预览和恢复均不会触发源码执行。
- FMT-009：导出前能够定位损失与过期结果；取消后原文档、目标文件和脚本启用状态不变。
- FMT-010：磁盘满、写入中断、替换失败、外部改写与恢复中断不破坏最后成功版本；连续编辑仍按恢复周期提交快照，在冻结的正常环境与批准负载下达到未落盘窗口预算；超时滞后与失败重试可见且有界；恢复候选不会携带执行授权。

验收同时检查语义与结构：重新读入比较领域快照，直接检查 ZIP/XML/JSON 的类型、关系与缓存标记。
语义保持不要求 ZIP 字节完全相同；承诺原样保留的未知条目则必须按解压字节比较。
发布支持矩阵必须与已通过的夹具对应，未覆盖能力继续标为“未验证”或“延期”。
